# /ttl-idea

Быстро сохранить сырую идею в `docs/ideas/NN_*.md` без лишних вопросов.

## Вход

Все, что написано после `/ttl-idea`, является "сырой" идеей.
Если первая строка выглядит как заголовок, использовать ее как основу для названия заметки.

## Что нужно сделать

- Создать **новый** файл в `docs/ideas/` с именем `NN_<slug>.md`.
  - `NN` = следующий номер: просканировать `docs/ideas/*.md`, взять максимальный двухзначный префикс `NN_` и сделать `NN+1` (с leading zero).
  - Если по какой-то причине имя уже занято, выбрать следующий свободный `NN`.
  - `<slug>` = короткий ASCII slug (lowercase, цифры, `_`), 3-8 слов. Если не получается, использовать `idea`.
- Писать **по-русски**.
- **Не добавлять YAML frontmatter**.
- В начале файла вставить исходный текст пользователя как HTML-комментарий и **исправить только опечатки** (смысл не менять):

```md
<!--
Исходная формулировка (исправлены опечатки, смысл сохранен):
...текст пользователя...
-->
```

- Дальше оформить заметку коротко и технически:
  - `## 1. Коротко` (1 абзац).
  - `## 2. Модель/термины` (узлы/ресурсы/метрика/окрестности).
  - `## 3. Как это применять` (маппинг/планирование/инварианты корректности).
  - `## 4. Диаграммы` (1-2 Mermaid диаграммы, если уместно).
  - `## 5. Связь с существующими идеями` (ссылки на релевантные `docs/ideas/*`).

## Ограничения (важно)

- Минимизировать диалог: **не задавать уточняющих вопросов**, если можно разумно продолжить по умолчанию.
- Не трогать другие файлы, кроме нового `docs/ideas/NN_*.md`.
- Mermaid: не использовать пробелы в node IDs; для edge-label с символами вроде `()` использовать кавычки.
