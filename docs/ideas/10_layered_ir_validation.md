# Контекст

Цель состоит в том, чтобы зафиксировать в tt-lang layered-структуру MLIR (L0..L6), которая:

- позволяет максимально долго оставаться в MLIR,
- делает валидацию LLK протоколов системной и CFG-aware,
- отделяет "семантику и контракты" от "формы C++/файлов и стиля",
- допускает arch-ветвления (`blackhole` vs `wormhole_b0`) как данные, а не как неявные ifdef.

## SDLC (локальный трекинг)

- **Статус**: документ готов как proposal; дальнейшие правки/уточнения возможны.
- **Архитектурный документ (SoT для этой инициативы)**:
  - `docs/01_Architecture/07_LLD_LayeredIR_TTMetal_LLkDbV2_Validation.md`
- **Намерение**: на базе этого дизайна в будущем добавить диалекты/OpInterfaces/passes для верификации контрактов LLK DB v2 и для поздней эмиссии C++.

## Границы

- Документ не требует немедленных изменений компилятора и не фиксирует конкретную реализацию 1:1.
- Псевдокод и названия диалектов в документе являются условными.

## Следующие шаги (если переходить к реализации)

- Выделить минимальный набор ресурсов LLK DB v2 для первой версии verifier'а: `CB`, `DST`, `SFPU`, `NOC`.
- Определить формат импорта LLK DB v2 (пер arch) в таблицы/атрибуты.
- Спроектировать `ResourceContractInterface` и pass `llk-verify-resource-states` (CFG-aware dataflow).
- Добавить lit-тесты для positive/negative кейсов verifier'а (в tt-lang или в соседнем проекте, где используется verifier).
