## 1. Алгоритмы и сравнение

**Пресеты алгоритмов размещения**:

- **RCW (Reader-Compute-Writer)** — фиксированный пресет: три стадии, один compute + два DM; эталон для сравнения.
- **Детерминированные**: много проходов заполнения ресурсов — например **Дейкстра** (кратчайший путь по графу ресурсов), **A\*** (с эвристикой); размещение нод по ядрам по весам рёбер (lat/bw, расстояния).
- **MCTS (AlphaGo-подобный)**: дерево поиска, просчёт и оценка вариантов размещения; семплирование действий, rollouts, оценка позиции.
- **AlphaStar-like**: вычисление «идеального» расположения нод на ресурсах с учётом динамики (буферы, занятость фабрик); стратегия размещения задаёт игру, динамика — сама игра (док 16).

**В UI**:

- Выбор алгоритма из списка (пресеты + зарегистрированные пользовательские).
- Добавление/удаление видов алгоритмов без изменения кода — плагинная модель или реестр алгоритмов (имя, фабрика env/policy, опциональные параметры).
- Сравнение двух и более планов: side-by-side по метрикам (утилизация, латентность, bottlenecks, reward) и визуально (карта размещения, граф с раскраской по ядрам).

## 2. Асинхронность и параллельные прогоны

- **Несколько прогонов одновременно**: пользователь запускает несколько инстансов (один и тот же или разные алгоритмы, один и тот же или разные входы); каждый прогон — отдельный поток или воркер (процесс/async task).
- **Независимые обновления в UI**: по каждому прогону состояние (placement, шаг, reward, метрики) передаётся в UI асинхронно — WebSocket или long-polling; UI отображает несколько прогонов (вкладки, панели или единый дашборд с несколькими строками/карточками).
- Требование: не блокировать UI при длительном прогоне; возможность видеть прогресс и промежуточные результаты по каждому прогону независимо.

## 3. Управление воспроизведением и отладка

- **Пауза/возобновление**: для любого запущенного алгоритма — поставить на паузу и снять с паузы; в паузе симуляция/поиск не продвигается, состояние доступно для просмотра.
- **Перемотка назад/вперёд**: история состояний по шагам (snapshots placement + опционально состояние симулятора); шаг вперёд/назад по этой истории без перезапуска алгоритма; «ползунок» времени/шага для навигации.
- **Лог решений**: для каждого прогона — лог «шаг → действие, аргумент» (например: шаг 3 — разместить node_id=2 на core (1,0)); просмотр в отдельной панели или вкладке; фильтрация и поиск.
- **Статистика в паузе**: в состоянии паузы — панель статистики: что алгоритм накопил по **нодам** (например, счётчики посещений, метки размещения, оценки) и по **отношениям** (рёбра графа, буферы, очереди — заполненность, латентность по рёбрам). Цель — понимать, почему алгоритм принял те или иные решения, и сравнивать с другими прогонами.

## 4. Симулятор: гибкая настройка параметров

- **Параметры симулятора вынесены в конфиг/UI**: не жёстко зашиты в коде; пользователь или оператор может менять без пересборки.
- **Что настраивать** (минимальный набор для «максимально гибкой» настройки):
  - **Граф и топология**: размер сетки (grid), веса рёбер (latency, bandwidth) по типам связей (L1/CB, NOC, LAN) или по парам ядер; опционально загрузка топологии из файла/замера.
  - **Симулятор динамики**: выбор движка — упрощённая дискретная модель (очереди, задержки по рёбрам, занятость блоков) или симулятор по док 15 (salabim); параметры очередей (размеры, таймауты), задержки по операциям.
  - **Алгоритмы поиска**: для MCTS — число семплов, глубина rollouts, температура; для A* — эвристика; для детерминированных — порядок обхода (топологический, по приоритету).
- **Подстановка симулятора**: интерфейс «reward_fn(graph, topology, placement)» или «run_simulation(placement) → trajectory/metrics»; подмена реализации (заглушка, упрощённая модель, salabim) без смены кода UI/backend, только конфиг или выбор в UI.

## 5. Визуализация в стиле AAA

- **Три вида** из док 16 сохраняются: вертикальный граф алго-нод; вид по ресурсам (FPU/SFPU/NOC с раскраской); HW-топология «на полу» (сетка/граф с расстояниями).
- **Стиль AAA** (целевые свойства, не обязательные сроки):
  - **Уровень детализации (LOD)**: переключение детализации — от высокоуровневой карты до деталей по отдельным нодам/рёбрам; при большом графе — свёрнутое представление и раскрытие по клику.
  - **Читаемость**: консистентная цветовая модель и легенда (док 12); подписи и тултипы по нодам/рёбрам; минимум визуального шума.
  - **Анимация динамики**: при наличии траектории симулятора — анимация заполнения буферов, занятости фабрик во времени; синхронизация с ползунком времени/шага.
- Цель: максимально удобно и понятно для принятия решений при сравнении алгоритмов и отладке.

## Итог

- **Алгоритмы**: пресеты RCW, Дейкстра, A*, MCTS, AlphaStar-like; добавление/удаление через реестр; сравнение планов по метрикам и визуально.
- **Асинхронность**: параллельные прогоны, независимые обновления в UI (WebSocket/polling).
- **Воспроизведение и отладка**: пауза, перемотка назад/вперёд, лог решений, статистика по нодам и связям в паузе.
- **Симулятор**: гибкая настройка параметров (граф, топология, веса, тип симулятора, параметры MCTS/A* и т.д.) в конфиге/UI.
- **Визуализация**: три вида из док 16; целевой стиль AAA — LOD, читаемость, анимация динамики.
- **Фазы**: граф и заглушка (14, 3–4) → UI и алгоритмы → динамика и симулятор → multi-algorithm и UX отладки.
