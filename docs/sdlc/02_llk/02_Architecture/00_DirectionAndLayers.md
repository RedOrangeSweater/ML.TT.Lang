# Направление и слои: Python test infra tt_llk

- **Статус**: актуально (Direction).
- **Аудитория**: разработчики Python test infra tt_llk, планировщики рефакторинга.
- **Связанные документы**: tt-lang [08_PythonDialectLayersAndDataFlow.md](../../00_Main/02_Architecture/08_PythonDialectLayersAndDataFlow.md) (слои + Pydantic), [02_Architecture/README.md](README.md).

## 1. Назначение

Документ фиксирует **целевое направление** для Python-части тестовой инфраструктуры tt_llk: явные слои с чёткими контрактами и валидацией **только в Pydantic** для входов и спецификаций. Ориентир — подход tt-lang (program/graph/compile/runtime с Pydantic request/response).

## 2. Слои (целевая схема)

| Слой | Содержимое | Контракт (типы) |
|------|------------|-----------------|
| **Input** | Файлы (YAML) и переменные окружения -> проверенные конфиги | Pydantic-модели для глобальных настроек и операций |
| **Spec** | Чистое «что запускать»: pipeline spec, operands spec | Pydantic или датаклассы с явными полями |
| **Build/Compile** | Spec -> сгенерированный C++ -> артефакты сборки (ELF) | Вход: Spec; выход: пути к артефактам |
| **Runtime/Execute** | Артефакты + выбор устройства -> выполнение на устройстве | Вход: артефакты + location; без ad-hoc проверок в бизнес-логике |
| **Results** | Сырые выходы устройства -> нормализованные результаты -> golden сравнения / отчёт | Явные типы для результатов и отчётов |

Границы между слоями — только явные типы; для Python-конфигов и спецификаций предпочтительны **Pydantic BaseModel**.

## 3. Правило валидации

**Валидация только в Pydantic:** проверки входов и выходов слоёв (форматы, enum-значения, обязательные поля, допустимые строки) выполняются **только в Pydantic-моделях** (field_validator, model_validator). В бизнес-логике (парсеры, генераторы кода, раннеры) не вызывают отдельные функции `validate_*`; контракты обеспечиваются при построении/валидации request/response моделей.

## 4. Текущий фокус рефакторинга

- **Fuser YAML**: парсинг и валидация конфигурации fused-тестов (глобальные поля, операции, math, sfpu) переводятся на Pydantic-модели; внешний API `load_fuser_config(test_name) -> FuserConfig` сохраняется.
- Дальнейшие шаги: по мере появления требований — выделение Spec-слоя, унификация конфигов других тестов.
- Миграция Spec-типов (GlobalConfig, FuserConfig) на Pydantic — опционально, по мере требований; не блокирует текущие улучшения.

## 5. Связь с tt-lang

Подход согласован с tt-lang: один фокус на слой, только Pydantic-типы на границах, переиспользуемые примитивы. Реестр слоёв и трансформаций ведётся в этом документе и в [08_PythonDialectLayersAndDataFlow.md](../../00_Main/02_Architecture/08_PythonDialectLayersAndDataFlow.md) для tt-lang.
